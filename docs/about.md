# 关于本项目

## 项目目标

这次实践的核心目标其实很直接：把本地写的几篇 Markdown 文档，通过 GitHub Actions 自动打包成静态网页，并直接发布到 GitHub Pages 上，跑通“本地改文档 -> `git push` -> 网页自动更新”这一整套流程。

## 技术组成

整个方案没用到任何需要自己维护的服务器或数据库，主要就是下面这四块拼起来的：

| 工具 / 服务 | 在项目里的作用 | 备注 |
| --- | --- | --- |
| Markdown | 编写文档正文、表格和代码块 | 纯文本格式，直接放进 Git 做版本管理很方便 |
| MkDocs Material | 把 `docs/` 里的 `.md` 编译成带搜索和导航的静态网页 | 默认配色和中文排版就已经挺好看了 |
| GitHub Actions | 监听 `main` 分支变动，在云端自动装依赖、跑构建和上传产物 | 配置文件在 `.github/workflows/deploy.yml` |
| GitHub Pages | 托管生成的 `site/` 静态产物并提供公开访问域名 | 直接走 Actions 产物发布，不用单开 `gh-pages` 分支 |

## 一点建站体会

先谈谈实际用下来的感受吧。之前搭个人博客 [vita.do](https://vita.do) 走的是 WordPress 那套路子，买 VPS、配环境、折腾备份什么的，多少还是得花点精力去管服务器。如果是平时写点随笔或者想深度折腾主题倒也还好，但真要拿来放课程笔记或者项目说明文档，其实就有点重了。

这次换成 MkDocs 配 GitHub Pages，整体上来说省心很多。文档本身全是本地的 Markdown，排版和全文搜索直接交给 Material 主题就行（自带的默认样式其实就已经挺顺眼了）。

本地改完往 `main` 分支一推，GitHub Actions 一分多钟就能把静态页构建发布好。说到底还是不用自己操心后端和机器维护，也不用担心哪天数据库崩了或者服务器到期，拿来做纯技术文档站确实要舒服不少。

顺带一提，如果你想看本地怎么跑起来预览，可以直接翻到下一页的 [使用指南](guide.md)，或者先回 [首页](index.md)。
